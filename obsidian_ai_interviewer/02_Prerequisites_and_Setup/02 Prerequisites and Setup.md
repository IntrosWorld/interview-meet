# 02 - Prerequisites and setup

## Required software and services

| Requirement | Why it is needed |
|---|---|
| Node.js 18 or newer | Runs the server and supplies modern JavaScript APIs |
| npm | Installs dependencies and invokes the development script |
| Modern Chromium-based browser | Best support for Web Audio and Web Speech APIs |
| Microphone | Supplies live candidate audio |
| Google AI Studio API key | Authenticates the server with Gemini |
| Git | Clones and versions the project |
| Obsidian, optional | Opens this documentation as a linked vault |

The current machine uses Node.js 22, which satisfies the repository’s requirement.

## Create the project from scratch

```powershell
New-Item -ItemType Directory ai_interviewer
Set-Location ai_interviewer
git init
npm init -y
```

Install runtime dependencies:

```powershell
npm install @google/genai hono ws dotenv @hono/node-server
```

Install development dependencies:

```powershell
npm install --save-dev tsx typescript @types/node @types/ws
```

What each package does:

- `@google/genai`: official Google Gen AI SDK, including `ai.live.connect`.
- `hono`: route definitions and HTTP response helpers.
- `@hono/node-server`: makes a Hono app listen through Node.
- `ws`: WebSocket server for browser connections.
- `dotenv`: loads key/value pairs from `.env` into `process.env`.
- `tsx`: executes TypeScript directly and watches files in development.
- `typescript`: compiler and type checker; useful even when `tsx` runs the code.
- `@types/node`, `@types/ws`: TypeScript declarations for Node and `ws`.

## Configure `package.json`

The important script in this project is:

```json
{
  "main": "server.ts",
  "scripts": {
    "dev": "tsx --watch --env-file=.env server.ts"
  }
}
```

Reading it from right to left:

1. `server.ts` is the entry file.
2. `--env-file=.env` loads the local environment file before execution.
3. `--watch` restarts after source changes.
4. `tsx` transpiles TypeScript in memory and runs it with Node.

The source also calls `dotenv.config()`. Using both mechanisms is redundant but harmless. A cleaner project would choose one.

## Create the environment files

`.env.example` is safe to commit:

```dotenv
GOOGLE_API_KEY=
```

Create a local `.env`:

```dotenv
GOOGLE_API_KEY=replace_with_your_real_key
PORT=8000
```

The `PORT` entry is optional because the server defaults to `8000`.

Create `.gitignore`:

```gitignore
node_modules/
.env
*.log
```

Why each line matters:

- `node_modules/` is regenerated by `npm install` and is very large.
- `.env` contains a credential.
- `*.log` contains local runtime output and may contain sensitive prompts.

## Suggested TypeScript configuration

The existing app runs without a checked-in `tsconfig.json`, because `tsx` chooses workable defaults. For a from-scratch production-quality version, add:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "noEmit": true
  },
  "include": ["server.ts"]
}
```

Then add a check script:

```json
"typecheck": "tsc --noEmit"
```

## First startup

```powershell
npm run dev
```

Expected server output includes:

```text
Connecting to Gemini Live API with model: ...
Live Session Opened Successfully
Server running on http://localhost:8000
```

Open `http://localhost:8000`. Enter/select an interview target and click **Start Interview** before expecting the UI status to change to **Connected**.

## Setup verification checklist

- [ ] `node --version` is 18 or newer.
- [ ] `npm install` completed.
- [ ] `.env` exists and is ignored by Git.
- [ ] `GOOGLE_API_KEY` is non-empty.
- [ ] port 8000 is not occupied by another process.
- [ ] the browser allows localhost microphone access.
- [ ] the terminal shows `setupComplete` from Gemini.
